## Fixed

Correctness (Phase 1, 2, 4, 5):
- Every ROM acceptance path now needs a snapshot captured before compile. The snapshot is re-checked
  inside the acceptance transaction (P1.4 step 3). This covers the local permuter, donated-compute jobs,
  autopilot and quiet tries (P1.5), and project symbols are now part of the snapshot (P1.3).
- Donated-compute jobs carry snapshot, policy and seed identities. Stale submissions are rejected (P5.8).
- A permuter turn is refunded when no candidate compiled because of an infrastructure failure. Compiled
  and improved turns and infra failures are counted (P1.2 items 2-3).
- Budget resets need a material improvement (at most 0.95x the previous best) and are capped at 3 per
  function (P1.2 items 6-7).
- `revalidate_bests` no longer marks an unreproduced legacy best as verified.
- ROM batches group by per-function compiler profile, count compiler invocations in telemetry and
  release partial claims on failure (P2.2).
- `calibrate_and_commit` refuses to commit without an accepted-match regression check (P4.1 item 7).
  `Network.calibrate_profile` runs a bounded, read-only calibration.
- On macOS, installing a Linux-only toolchain now gives the Docker message instead of the WSL one.
- Context-less projects are no longer reported as "context changed".
- REA spawn failures raise `ReaProviderFailure` and no longer crash with a raw OSError.
- Failed cache publishes no longer leave temp files behind.

Opt-in until measured (exit gates of P5 and P6):
- Guided beam search: `DECOMPNET_GUIDED_SEARCH=1`. The default is single-trajectory search.
- Structural rerank: `DECOMPNET_STRUCTURAL_RERANK=1`.
- REA provider: `DECOMPNET_REA_PROVIDER=1`.

  - Fork objdiff results are normalised to the shared summary.
  - Receipts record the candidate object digest and the actual link tier.
  - A `call_reference` mismatch class and routing row were added.
  - The score-only fast path uses an authoritative verdict.

## Section 18 contracts

Tests: `tests/test_section18_contracts.py` (27 tests).

- **Function identity (18.2).** New `function_identity` table (one row per function id), not new
  columns:
  - Fields: schema version, artifact sha256, module, unit, address space, entry kind, entry (exact
    lower-case hex string) and section.
  - Name and revision are read from `functions` when serialising (`Store.identity`), so a rename never
    leaves a stale copy.
  - Object imports use the section plus a section-relative offset. ROM, GBA and GB imports use the load
    address, with the segment or bank as the address space, because overlays and banks reuse addresses.
  - A matched function keeps the identity it was matched under when its project is re-imported.
  - Migration: `CREATE TABLE IF NOT EXISTS` plus a backfill on every open. The backfill removes orphaned
    rows and fills gaps, and is idempotent.
  - Downgrade: an older version writing directly to the database still works, and the next open
    repairs it.
- **Configuration schema (18.9).** `project.validate_config` governs the `matching`, `search`,
  `analysis`, `rea` and `retrieval` blocks:
  - Unknown keys and wrong types inside those blocks are rejected.
  - `analysis.allow_target_byte_mutation = true` and `rea.read_only = false` are refused.
  - `rea.enabled` needs a pinned artifact and schema digest.
  - `import_project` enforces the schema. The retrieval parser in `network.config_from` uses the same
    schema, so `retrieval.holdout` is now accepted there too.
  - Diagnostic: `decompnet config <project dir>` (`project.effective_config`) shows every value and
    where it came from (default, project or a `DECOMPNET_*` variable). Optional features default off.
- **Evidence records (18.5).** `EvidenceRecord` (in `analysis/contracts.py`) and
  `analysis/evidence_store.py` save records to the `evidence_records` and `evidence_payloads` tables:
  - Records carry per-facet status and payload refs, the route, the engine and its version, the
    analysis-profile digest (route keys stripped), the correlation group and the snapshot. They are
    always marked as untrusted target content.
  - Payloads are content-addressed and written in the same transaction. A record can never point at a
    missing or mismatched payload.
  - Evidence ids are deterministic, so saving the same evidence twice is a no-op.
  - Wiring: the coordinator's broker saves every fresh, successful fetch and adds an
    `evidence:<function>` ref to the bundle. A storage failure becomes a bundle diagnostic and is not
    raised.
  - Takedown: `project remove` deletes the project's identities, its evidence records and every
    payload that no remaining record references.
  - Hash-only projects never reach the broker, because escalation needs target bytes the coordinator
    does not hold for them.

Section 18 contracts: built later on 16 Oct 2026 (see "Section 18 contracts" above). What remains:
- A re-import does not bump `functions.revision` when a target changes (18.2 asks for a new revision).
- The configuration schema is validated and diagnosed, but the runtime still reads the three
  `DECOMPNET_*` variables, not the project's `[search]`/`[analysis]`/`[rea]` values. Most `matching`,
  `search` and `analysis` keys are declared only.
- Functions added by forks, rescans and older writers get their identity only at the next database
  open (until then `Store.identity()` returns None). That identity has a NULL artifact digest and,
  without a load address, `entry_kind = 'unknown'`.
- ROM, GBA and GB identities hash the identified program image written to the work folder, not the
  file the user supplied (for example a disc image).
- Evidence is persisted only for fresh broker fetches. Coalesced and reused bundles point at the same
  record, and there is no cleanup or retention policy for old records yet.

Smaller items:
- Permuter eligibility by mismatch category (P5.4).
- A compiled round-trip test for unmodified parser inputs (P5.2; needs a compiler lane).
- A remedy for literal/data mismatches beyond blocking generic permutation.
- Ghidra/REA fields in `baseline-manifest.json` were inventoried later (see `real-lanes/`).
- Snapshot symbol digests are passed only on the main attempt and batch paths.
