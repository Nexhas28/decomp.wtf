# Forks of public decomps and scratch projects

A **fork** plugs decomp.wtf's agents into an existing decompilation project as it is: its own build system and compilers, judged by objdiff[^forksinit].

## Project layouts set up automatically (`forks/project.py`)

- **manifest**: the project ships `.decomp.wtf.json` with `game` and `setup` commands.
- **dtk**: dtk-template GameCube/Wii projects (`configure.py` + `config/<version>/config.yml`, built with ninja). The disc goes in `orig/<version>/`.
- **configure**: other `configure.py` + ninja projects.
- **splat**: N64/PlayStation-style projects (splat yaml + Makefile). The game file is checked against the yaml's sha1.

Other layouts are set up by the user following the project's README. decomp.wtf takes over once the build produces `objdiff.json`[^forkproject].

## Catalog and AI policy

decomp.dev retired its project directory on 2026-10-15 (`projects.json` answers 410 Gone)[^catalog]:

- decomp.wtf no longer queries it. An install shows a previously downloaded list, if any.
- Public decomps are forked by repository address[^catalog].
- **Note:** the README's "245 projects on decomp.dev" predates this[^readme].

Before cloning, `forks/policy.py` reads the project's README, CONTRIBUTING and agent files through a partial clone, and shows their lines about AI word for word[^policy].

## The loop and guard rails (`app/forkengine.py`)

Agents claim functions and write them into the project's real source files. `forks/csource.py` handles real definitions and `INCLUDE_ASM`/`GLOBAL_ASM` stubs[^csource]. The engine builds just that unit and lets objdiff judge. A 100% match is committed to a local git branch[^forkengine].

Guard rails[^forkengine]:

- Agents may write only C/C++ sources and headers.
- Inline assembly is refused.
- A header edit is undone if it costs a single match.

Drafts come from m2c for MIPS, PowerPC and ARM/Thumb[^drafts].

`forks/literals.py` compares the constant values a matched function loads with the original's. objdiff's `functionRelocDiffs: none` rule would otherwise accept a wrong float[^literals].

## From matched to linked (dtk-template)

- `forks/dtksplits.py` parses and writes `splits.txt` and `configure.py`. The engine keeps a layout change only when the game still builds byte for byte[^dtksplits].
- `forks/datadiff.py` shows a file's data sections next to the original's, which is what keeps a file from linking once its functions match[^datadiff].

## Scratch projects

GameCube, Wii and DS games imported from scratch become fork-style projects, generated by `forks/scratch_dtk.py` and `forks/scratch_dsd.py`. See [platforms](/project/platforms.md) and [ROM import](/project/rom-import-pipeline.md).

For objdiff, dtk and dsd themselves, see the [tool concepts](/tools/index.md).
